# 使用指南

## 运行环境

- Windows 10 / 11，64 位。
- Windows 发布包自带 Python 运行环境，解压后即可运行界面。
- FFmpeg 和 ffprobe 单独安装。支持 **NVIDIA (NVENC) / Intel (QSV) / AMD (AMF)** 10-bit HEVC 显卡硬件加速，也可在无独显或硬编不可用时完全使用 CPU (`libx265`) 运行。
- HDR 文件需要相应设备和播放器才能显示其完整亮度范围。

FFmpeg 应包含 `zscale`、`colorchannelmixer`、`lut1d`、`lut3d`、`libx265`、`framehash`；使用音效时还需 `extrastereo`、`stereowiden`、`volume`、`alimiter`。使用显卡硬件加速时需较新完整 FFmpeg（支持 `-mastering_display`、`-content_light` 及 `hevc_nvenc` / `hevc_qsv` / `hevc_amf`）；使用杜比视界转换时，Profile 8.1/7 无损直剥需要 `dovi_rpu`（Profile 7 另需 `dovi_split` 或 `filter_units`），Profile 5/8.4 色彩还原需要 `libplacebo` 及支持 Vulkan 的显卡驱动。

可通过 [FFmpeg 下载页](https://ffmpeg.org/download.html)寻找 Windows 构建。程序依次查找自身 `bin` 文件夹、同目录、系统 `PATH` 和常见 WinGet 安装目录。

```text
SDR2HDR/
  SDR2HDR.exe
  bin/
    ffmpeg.exe
    ffprobe.exe
```

## 普通 SDR 转 HDR

1. 选择视频和新的导出文件名。
2. 选择输出尺寸与 **HDR 风格**（默认“影院均衡高光（推荐电影·1000 nit）”）。默认保持原尺寸，不插帧；调整尺寸不会恢复原片没有的细节。
3. 选择编码方式、编码器（默认“自动（优先显卡加速）”）、音效以及 **完成后动作**（可选“完成后自动关机”或“完成后进入待机”）。
4. 先点击 **自定义试转…**（默认自动定位视频正中 30 秒，可拖动时间轴或输入起点／时长）检查亮度、颜色和声音，再点击 **导出完整 HDR** 立刻转换，或点击 **加入任务列表** 排队批量转换。

### HDR 风格选择

- **影院均衡高光（默认，1000 nit）** 提亮暗部，在接近白点时逐渐减小高光增幅。
- **柔和暗室保护（450 nit）**（CLI：`--style natural`）：保留 `BT.1886 (Gamma 2.4)` 温和暗室风格（`190 nits` 漫反射基准、`450 nits` 峰值、`MaxCLL/MaxFALL = 450/200`），适合全黑环境观影或偏好低刺眼高光的片源。
- **高对比风格（原版·动漫）**（CLI：`--style vivid`）：保留 v1.4 及以前版本的非线性对数曲线与色差调整，暗部更沉、亮部更锐利艳丽，适合二次元动漫与暗场景；在明亮实拍人脸上可能偏亮。

注：当输入为杜比视界（DV）或已有标准 HDR10 视频时，“HDR 风格”下拉框会自动锁定，仅对普通 SDR 输入生效。

程序支持常见容器中的逐行扫描 BT.709 / BT.601 SDR 视频。当前不直接处理隔行扫描、其他广色域 SDR 或未支持的 HDR 转换场景。

输入缺失可选数值时，程序优先使用可用信息；进度暂时不可用时继续等待。颜色信息缺失时，会在输入信息中显示所采用的推定值。

## 编码器与显卡加速

启动或转换前，程序会自动进行 2 帧硬件编码自检，确认本地显卡、驱动和 FFmpeg 同时满足以下条件才启用对应显卡加速：

- 支持 HEVC Main 10（`p010le` 10-bit）硬件编码；
- 能够把 BT.2020、PQ（SMPTE ST 2084）、`hvc1` 与 `Mastering display` / `Content light` HDR10 静态元数据正确写入 MP4。

可选编码器如下：

- **自动（优先显卡加速）**：按 `NVIDIA NVENC > Intel QSV > AMD AMF > CPU (x265)` 的顺序自动启用可用编码器。若输出分辨率不在硬件支持范围（`160×128` 至 `8192×8192`），或所选“画面无损编码”不被当前显卡支持，会自动回退到 CPU (`x265`)。
- **NVIDIA 显卡 (NVENC)** / **Intel 显卡 (QSV)** / **AMD 显卡 (AMF)**：强制使用指定显卡硬件加速；若本地环境不支持或规格不满足会明确提示原因。
- **CPU 软件编码 (x265)**：始终使用 `libx265` 软件编码，速度较慢但兼容性最广，同体积下压缩率通常更高。

v1.6.1 修订版中，GUI 和命令行默认的 `--gpu-filter auto` 会在普通 SDR 显卡有损转换时优先使用通过自检的 Vulkan 滤镜。HEVC / AV1 在条件满足时使用 Vulkan 硬解。H.264 由 CPU 解码。软件解码和回退的 CPU 滤镜各限 1～4 个线程。选择 `--gpu-filter simd` 可使用之前的高速 CPU 滤镜搭配显卡编码，适合优先考虑吞吐量的任务。

### 编码画质校准与 NVENC 双遍分析

- **全编码器码率均衡校准（v1.6.0）**：统一采用 4 秒关键帧间隔（`-g fps×4`）并校准各编码器质量刻度——NVENC `CQ 25 / 23 / 21`、Intel QSV `ICQ 23 / 21 / 19`（支持时自动开启 `extbrc / mbbrc`）、AMD AMF `CQP 25 / 23 / 21`、CPU `libx265 CRF 21 / 19 / 18`，在保持扎实 10-bit HDR10 细节的同时避免导出体积无故翻倍。
- **NVENC 双遍分析 (Multipass)**：默认不勾选（“精细画质”默认采用高速单遍 `p6 / VBR CQ 21 / spatial-aq`）；只有在追求极限码率分配且不介意耗时增加约 30%～80% 时，才建议勾选界面中的 **NVENC 双遍分析 (更慢)**（命令行：`--multipass`）。

## 批量任务列表、暂停／继续、停止保留与自动关机

- **任务列表**：选好参数后既可直接点 **导出完整 HDR** 立刻执行，也可点 **加入任务列表**（或 **批量添加视频…**），再点 **开始队列** 依次执行列表中的 1 项或多项任务；支持上移、下移、移除、清理已完成与清空列表。
- **暂停 / 继续**：转换进行中随时点击 **暂停** 挂起底层编码进程（冻结已用时间与 ETA），点击 **继续** 无缝恢复。
- **停止并保留**：编码中点击可向 FFmpeg 发送优雅退出信号，封包为可直接播放的 `原文件名_已转片段`；若在“画面无损编码”99% 逐帧校验阶段点击，则会立即跳过耗时校验并直接保留已完整编码的无损视频文件。
- **取消**：立即终止转码并清理未完成的临时文件，原片始终保持不变。
- **完成后动作（自动关机 / 待机）**：可在任务开始前或运行期间选择“完成后自动关机”或“完成后进入待机（睡眠）”；全片或整个队列顺利完成后弹出 **60 秒倒计时窗口**，可随时点击取消保持开机（试转与手动取消不会触发）。

## 杜比视界（DV）转 HDR10

选择任意杜比视界视频（MP4 / MKV / MOV 等），程序会自动读取容器配置记录与首帧 RPU 元数据，并按 Profile 选择最佳路径：

- **Profile 8.1（含 HDR10 兼容层）**：不重编码，使用 `dovi_rpu=strip=1` 直接剥离 RPU 与 `dvcC` 配置盒，保留原生 10-bit HDR10 视频流，秒级完成、零画质损失。
- **Profile 7（双层蓝光）**：不重编码，使用 `dovi_split=mode=bl,dovi_rpu=strip=1` 保留 10-bit HDR10 基础层（BL）并剥离增强层（EL）与 RPU（注：不烘焙 FEL 增强层的额外亮度增量）。
- **Profile 5（IPTPQc2，普通屏幕偏绿偏紫）与 Profile 8.4（HLG 杜比视界）**：由于没有标准 HDR10 基础层，程序自动通过 `libplacebo`（`apply_dolbyvision=true`）将画面还原为标准 10-bit PQ / BT.2020，再交由已选显卡硬编或 CPU 编码输出，并彻底清除残留的杜比视界元数据标记。

在无损直剥模式下，界面会自动锁定尺寸、画质和编码器，但仍可选择原声保留或双声道虚拟环绕音效，也支持 10 秒试转。

## 给已有 HDR 加音效

选择 HEVC、10-bit、YUV 4:2:0、PQ / BT.2020 的 HDR MP4，再选择“虚拟环绕（双声道）”。

此时尺寸和画面编码设置会禁用。程序直接复制原视频轨道，只处理音频，避免重复增强和视频重编码。

## 音效、音轨勾选与内嵌字幕

程序采用 **同封装默认导出**（原片 `.mkv` 默认导 `.mkv`，原片 `.mp4` 默认导 `.mp4`），并可在界面点击 **「勾选音轨 / 字幕…」** 自由勾选保留或丢弃任意音轨与内嵌字幕（完整保留语言与轨道标题标签）：

- **原声（保留）· 导出 `.mkv`**：几乎所有已选音轨（含 `TrueHD Atmos / DTS-HD MA / EAC3 / AC3 / AAC / FLAC / PCM`）与所有内嵌字幕（含 `SRT / ASS / SSA / 蓝光 PGS / VobSub` 及 ASS 字体附件）均直接 `-c:a copy` / `-c:s copy` 100% 无损保留。
- **原声（保留）· 导出 `.mp4`**：原生兼容的 `AAC / AC3 / EAC3 (DDP Atmos) / DTS / FLAC / ALAC / MP3 / Opus`（无论 `2.0`、`5.1` 还是 `7.1`）直接无损直拷，文本字幕自动转为 `mov_text`；若已选轨道包含 MP4 不支持直拷的音轨（如 `TrueHD / PCM`）或蓝光图形字幕（`PGS / VobSub`），开始前会弹窗提醒用户可一键改存 `.mkv` 无损直拷，或继续导出 `.mp4`（不兼容音轨按原声道数高码率转 AAC，图形字幕跳过）。

**虚拟环绕（双声道）**通过声场扩展、短交叉延迟和限幅，对勾选的第一条音轨产生更宽的双声道声场，然后编码为 48 kHz、320 kbps AAC。它不生成离散的 5.1 / 7.1 声道或物体音频。

播放已处理文件时，额外叠加另一套画质或空间音效会改变结果。对比时应使用相同播放器、屏幕和音量设置。

## 无损档

“画面无损编码”使用 HEVC 的无损编码模式，并核对每帧原始像素字节数和 SHA-256 摘要。CPU (`libx265`) 与经自检支持的 NVIDIA NVENC 均可执行无损编码；Intel QSV 与 AMD AMF 不支持 10-bit HEVC 无损，选择“自动”时会自动改用 CPU (`x265`) 完成无损导出。

- 校验基准是 HDR 处理完成后的 `yuv420p10le` 画面。
- 颜色映射、尺寸变换、色度采样和 10-bit 量化仍属于转换过程。
- 音频规则与其他档位相同，不承诺音频无损。
- 文件可能比原片大很多，部分播放器需要软件解码。
- 进度到 99% 后还可能在逐帧校验，界面会说明当前阶段。
- 不一致的输出不会保存为最终文件；取消任务会清理未完成的副本。

建议从原始 SDR 文件导出。把已有的有损 HDR 文件重新编码成无损文件，不能恢复之前丢失的细节。

## 文件检查和记录

导出时检查编码、色深、PQ / BT.2020 标记、尺寸、时长、音轨和 HDR10 静态元数据。无损档额外检查全片像素一致性。

同名 `.hdr.json` 文件记录版本、转换选项、输出检查和无损校验结果。记录包含输入和输出文件路径，不需要上传到视频平台。

程序拒绝覆盖原片或已有输出文件。如果路径已被占用，请改用新文件名。

## 视频平台投稿

使用导出的 MP4 作为投稿源，等待平台转码，再检查实际可选画质和 HDR 档位。

工具不会登录或发布到平台，也不能保证平台接收所有编码组合。无损文件主要用于保存母版；如投稿端不接受或体积不合适，可从原片另导出精细档。

平台播放版本可能再次有损压缩。平台处理、显示器和播放器色调映射均会影响最终观感。
