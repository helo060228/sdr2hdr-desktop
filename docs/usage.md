# 使用指南

## 运行环境

- Windows 10 / 11，64 位。
- Windows 发布包自带 Python 运行环境，解压后即可运行界面。
- FFmpeg 和 ffprobe 单独安装。本项目的转换流程使用 CPU，不依赖特定显卡。
- HDR 文件需要相应设备和播放器才能显示其完整亮度范围。

FFmpeg 应包含 `zscale`、`colorchannelmixer`、`lut1d`、`libx265`、`framehash`；使用音效时还需 `extrastereo`、`stereowiden`、`volume`、`alimiter`。

可通过 [FFmpeg 下载页](https://ffmpeg.org/download.html)寻找 Windows 构建。程序依次查找自身 `bin` 文件夹、同目录、系统 `PATH` 和常见 WinGet 安装目录。

```text
SDR2HDR/
  SDR2HDR.exe
  bin/
    ffmpeg.exe
    ffprobe.exe
```

## 普通 SDR 转 HDR

1. 选择视频和新的导出文件名。
2. 选择输出尺寸。默认保持原尺寸，不插帧；调整尺寸不会恢复原片没有的细节。
3. 选择编码档位和音效。
4. 先试转 10 秒，检查亮度、颜色和声音，再导出全片。

程序支持常见容器中的逐行扫描 BT.709 / BT.601 SDR 视频。当前不直接处理隔行扫描、其他广色域 SDR 或未支持的 HDR 转换场景。

输入缺失可选数值时，程序优先使用可用信息；进度暂时不可用时继续等待。颜色信息缺失时，会在输入信息中显示所采用的推定值。

## 给已有 HDR 加音效

选择 HEVC、10-bit、YUV 4:2:0、PQ / BT.2020 的 HDR MP4，再选择“虚拟环绕（双声道）”。

此时尺寸和画面编码设置会禁用。程序直接复制原视频轨道，只处理音频，避免重复增强和视频重编码。

## 音效

**原声（保留）**关闭额外空间效果。符合条件的双声道 AAC 会直接复制；其他音频会转为 48 kHz 双声道 AAC。

**虚拟环绕（双声道）**通过声道差分增强、短交叉延迟和限幅，产生更宽的双声道声场，然后编码为 48 kHz、320 kbps AAC。它不生成离散的 5.1 / 7.1 声道或物体音频。

播放已处理文件时，额外叠加另一套画质或空间音效会改变结果。对比时应使用相同播放器、屏幕和音量设置。

## 无损档

“画面无损编码”使用 HEVC 的无损编码模式，并核对每帧原始像素字节数和 SHA-256 摘要。

- 校验基准是 HDR 处理完成后的 `yuv420p10le` 画面。
- 颜色映射、尺寸变换、色度采样和 10-bit 量化仍属于转换过程。
- 音频规则与其他档位相同，不承诺音频无损。
- 文件可能比原片大很多，部分播放器需要软件解码。
- 进度到 99% 后还可能在逐帧校验，界面会说明当前阶段。
- 不一致的输出不会保存为最终文件；取消任务会清理未完成的副本。

建议从原始 SDR 文件导出。把已有的有损 HDR 文件重新编码成无损文件，不能恢复之前丢失的细节。

## 文件检查和记录

导出时检查编码、色深、PQ / BT.2020 标记、尺寸、时长、音轨和 HDR10 静态元数据。无损档额外检查全片像素一致性。

同名 `.hdr.json` 文件记录版本、转换选项、输出检查和无损校验结果。记录包含输入和输出文件路径，不需要上传到视频平台。

程序拒绝覆盖原片或已有输出文件。如果路径已被占用，请改用新文件名。

## 视频平台投稿

使用导出的 MP4 作为投稿源，等待平台转码，再检查实际可选画质和 HDR 档位。

工具不会登录或发布到平台，也不能保证平台接收所有编码组合。无损文件主要用于保存母版；如投稿端不接受或体积不合适，可从原片另导出精细档。

平台播放版本可能再次有损压缩。平台处理、显示器和播放器色调映射均会影响最终观感。
